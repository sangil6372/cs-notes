## 태평양을 건너야 할까?

`google.com`을 입력했다. 구글 서버는 미국에 있을까? 대부분은 이렇게 생각한다. 한국 → 태평양 → 미국 → 구글.

만약 이게 사실이라면 웹페이지 하나를 열 때마다 태평양을 왕복해야 한다. 엄청 느릴 것이다. 그런데 현실에서 유튜브는 거의 바로 열린다. 왜일까?

택배로 생각해 보자. 전국에 물류센터가 있다. 서울 사람이 주문했는데 택배회사가 굳이 부산 센터에서 보낼까? 아니다. 가장 가까운 서울 센터에서 보낸다.

구글도 똑같다. 서버가 한 곳에 있지 않다. 한국, 일본, 싱가포르, 미국, 독일, 프랑스… 전 세계에 데이터센터와 캐시 서버가 흩어져 있다. 그래서 한국에서 접속하면 미국까지 갈 필요가 없는 경우가 많다.

## CDN — 이름부터 보자

**Content Delivery Network.** Content는 내용, Delivery는 전달, Network는 여러 곳에 있는 서버들. 즉 **콘텐츠를 가까운 곳에서 전달하는 네트워크**다.

유튜브 영상 하나를 100만 명이 본다고 하자. 미국 서버만 있다면 태평양 케이블이 그 트래픽을 전부 감당해야 한다. 그래서 미리 가까운 서버에 복사해 둔다.

왜 유튜브가 빠른지 여기서 보인다.

## DNS는 어떻게 한국 서버를 알려줄까?

DNS가 이렇게 판단하는 방식이 있다. "접속한 사람이 한국이네. 한국 서버 IP를 주자." 이걸 **Geo DNS**라고 한다. 접속자의 위치를 참고해서 가까운 서버의 IP로 응답하는 것이다.

그런데 더 신기한 기술이 있다.

## Anycast — 같은 주소가 여러 곳에

서울역이 전국에 100개 있다고 상상해 보자. 이상하다. 그런데 전화번호는 전부 같다. 걸면 가장 가까운 서울역으로 자동 연결된다.

인터넷에서는 이게 실제로 가능하다. 여러 서버가 **같은 IP 주소를 광고한다.**

<Chain items={[
  { label: "한국 서버 203.x.x.x" },
  { label: "일본 서버 203.x.x.x" },
  { label: "싱가포르 서버 203.x.x.x" },

IP는 같다. 그런데 라우터들이 생각한다. "가장 가까운 `203.x.x.x`는 여기네. 이쪽으로 보내자." 이게 **Anycast**다.

즉 DNS가 가까운 서버를 알려주는 경우도 있고, **라우팅 자체가** 가장 가까운 서버를 고르는 경우도 있다.

## 그럼 CDN = Anycast일까?

아니다. 자주 함께 쓰이지만 같은 기술이 아니다.

| | CDN | Anycast |
| --- | --- | --- |
| 무엇인가 | 콘텐츠를 여러 지역에 복제하는 전략 | 같은 IP를 여러 지역에서 서비스하는 라우팅 기술 |
| 답하는 질문 | "무엇을 어디에 둘까?" | "어느 서버로 보낼까?" |
| 동작 계층 | 콘텐츠 배치 | 네트워크 경로 |

대형 서비스들은 둘을 함께 쓰는 경우가 많다.

<Deeper>

- **Geo DNS는 생각보다 자주 틀린다.** 권한 서버에 도착하는 건 사용자 IP가 아니라 **리졸버의 IP**다. 그래서 한국 사용자가 `8.8.8.8`을 쓰면 리졸버 위치 기준으로 엉뚱한 서버를 받을 수 있다. 이걸 보완하려고 리졸버가 사용자 대역 일부를 같이 전달하는 <strong>EDNS Client Subnet(ECS)</strong>이 나왔다.
- **Anycast는 "가장 가까운"이 아니라 "라우팅상 가장 가까운" 곳으로 간다.** 물리적 거리가 아니라 BGP 경로 기준이라, 지도상 더 가까운 서버를 놔두고 다른 나라로 붙는 일도 생긴다.
- **CDN의 진짜 어려운 부분은 배치가 아니라 무효화다.** 콘텐츠를 복사해 두는 건 쉽다. 원본이 바뀌었을 때 전 세계 캐시를 언제 어떻게 버릴지(`Cache-Control`, purge)가 실제로 사고가 나는 지점이다. 잘못 설정하면 사용자가 며칠 전 화면을 계속 본다.

</Deeper>

## 은행에서는?

은행도 모든 시스템을 서울 본점 한 곳에서만 돌리지 않는다. 본센터, 재해복구센터(DR), 백업센터처럼 여러 거점에 시스템을 둔다.

다만 목적이 다르다. 은행의 계정계는 유튜브처럼 콘텐츠를 복제해 아무 서버나 응답하게 만드는 구조가 아니다. **정확성과 데이터 일관성**이 훨씬 중요하기 때문에, CDN과는 다른 방식으로 이중화와 장애 대응을 설계한다. 잔액이 서버마다 다르면 안 되니까.

<Key>

인터넷이 빠른 이유는 선이 특별히 빠르기 때문만이 아니라, **필요한 데이터를 사용자 가까이에 미리 배치**하기 때문이다.

CDN은 콘텐츠를 여러 지역에 복제하고, Geo DNS는 사용자 위치에 맞는 서버를 알려줄 수 있으며, Anycast는 같은 IP를 가진 여러 서버 중 네트워크적으로 가장 가까운 곳으로 트래픽을 보낸다.

</Key>
