## 절반만 맞는 비유

많은 책이 이렇게 시작한다. "DNS는 인터넷의 전화번호부입니다." 틀린 말은 아니다. 하지만 절반만 맞다.

휴대폰에 "엄마"를 저장해 두면 `010-1234-5678`을 외우지 않아도 된다. 이름만 누르면 휴대폰이 숫자를 대신 찾아준다. DNS도 비슷하다. `google.com`을 넣으면 `142.xxx.xxx.xxx`가 나온다.

그런데 여기서 중요한 질문. **왜 이름을 만들었을까?**

## 처음엔 그냥 파일 하나였다

인터넷 초창기에는 컴퓨터가 몇 대 없었다. 그래서 파일 하나에 이렇게 적어뒀다.

```text
142.250.xxx.xxx   google.com
223.xxx.xxx.xxx   naver.com
```

컴퓨터는 이 파일을 보고 찾아갔다. 이 파일 이름이 바로 **hosts**다. Windows의 `C:\Windows\System32\drivers\etc\hosts`가 왜 아직도 존재하는지, 여기서 조금 보인다.

그런데 인터넷이 커졌다. 100대에서 1,000대로, 100만 대로, 50억 대로. 이 파일을 매일 전 세계에 복사한다? 불가능하다.

그래서 생각을 바꿨다. **"가지고 있지 말고, 그냥 물어보자."** 이게 DNS다.

## 실제로 일어나는 일

브라우저에 `google.com`을 입력하면 컴퓨터는 먼저 이렇게 생각한다. "IP를 모르는데?" 그래서 DNS 서버에게 묻는다.

우리가 한참 공부했던 TCP보다도 **DNS가 먼저**라는 것이 여기서 보인다.

## 매번 물어볼까?

유튜브를 1분에 100번 들어간다고 하자. 매번 "google.com이 뭐죠?"라고 묻는 건 엄청나게 비효율적이다. 그래서 컴퓨터는 한 번 받은 답을 **기억한다.** 이것이 **DNS Cache**다.

그런데 영원히 기억하면 문제가 생긴다. 구글이 서버를 `142.xxx`에서 `35.xxx`로 옮겼는데 내 컴퓨터는 예전 주소를 붙들고 있으면, 엉뚱한 곳으로 간다.

그래서 기억에도 유효기간이 있다. 이게 <strong>TTL(Time To Live)</strong>이다. `TTL = 300`이면 5분 동안만 기억하고, 지나면 다시 묻는다.

## DNS 서버도 모르면?

DNS 서버라고 세상 모든 이름을 알고 있는 건 아니다. 모르면 **다른 DNS 서버에게 묻는다.**

서울에서 친구 집을 찾는 것과 비슷하다. 대한민국 → 서울 → 강남구 → 테헤란로 → 123번지. DNS도 `.` → `com` → `google` → IP 순으로 좁혀 간다.

## 도메인은 오른쪽부터 읽는다

그래서 도메인 이름 자체가 계층 구조다. `www.google.com`을 **오른쪽부터** 읽어야 의미가 맞는다.

<Chain items={[
  { label: ".", note: "루트" },
  { label: "com", note: "최상위 도메인(TLD)" },
  { label: "google", note: "이 이름의 주인" },
  { label: "www", note: "그 안의 호스트" },
]} />

대부분 왼쪽부터 읽지만, DNS는 오른쪽부터 의미를 가진다.

여기서 하나 더. 우리가 `www.google.com`이라고 쓰지만 정확하게는 마지막에 점이 하나 더 붙은 `www.google.com.`이다. 맨 끝의 `.`이 루트를 뜻한다. 브라우저와 운영체제가 자동으로 붙여주기 때문에 볼 일이 거의 없을 뿐이다.

<Deeper>

- **"통신사 DNS"의 정확한 이름은 재귀 리졸버(recursive resolver)다.** 위 그림에서 오해하기 쉬운 부분인데, 루트·TLD·권한 서버는 직접 답을 찾아주지 않는다. "나는 모르고 저쪽이 안다"고 알려줄 뿐이다. 실제로 단계마다 뛰어다니는 건 리졸버 혼자다. `8.8.8.8`(구글), `1.1.1.1`(Cloudflare)이 바로 이 리졸버를 공개해 둔 것이다.
- **hosts 파일은 지금도 DNS보다 먼저 조회된다.** 순서는 브라우저 캐시 → OS 캐시 → hosts → 리졸버. 그래서 로컬 개발에서 특정 도메인을 내 PC로 돌릴 때 아직도 hosts를 쓴다.
- **서버 이전 전에는 TTL을 미리 낮춘다.** TTL이 짧으면 전환은 빠르지만 조회량이 늘어난다. 그래서 평소엔 길게 두다가, 이전 며칠 전에 `300`초 같은 값으로 낮춰두고 작업한 뒤 다시 올리는 게 실무 관행이다.
- **DNS는 전통적으로 UDP 53번을 쓴다.** 응답이 커지면 TCP로 넘어간다. 평문이라 중간에서 어떤 사이트를 조회했는지 다 보이는데, 이걸 가리려고 나온 것이 DoH(HTTPS로 감싸기)와 DoT(TLS로 감싸기)다.

</Deeper>

DNS는 단순한 전화번호부가 아니라, **전 세계에 분산되어 있는 계층형 이름 조회 시스템**이다.

컴퓨터는 속도를 위해 DNS Cache를 쓰고, 주소가 바뀔 수 있기 때문에 TTL이 지나면 다시 조회한다.
